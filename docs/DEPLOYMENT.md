# Obsidian + Supabase Integration: Deployment Guide

## Overview

This is the LOOVE fork of SupaBase Jump with three additions:
1. *System vault awareness* — syncs notes generated by Postgres triggers alongside user notes
2. *Translation layer SQL* — projects operational tables into vault_files as markdown
3. *RAG pipeline* — automatic pgvector embeddings with semantic search

## Prerequisites

- Obsidian installed (desktop or mobile)
- LOOVE Supabase project access
- Supabase Management API PAT (for one-click setup)

## Deployment Order

### Stage 1: Plugin Setup
1. Install the forked plugin via BRAT:
   - BRAT > Add Beta Plugin > `loovelabs/obsidian-supabase-jump-1`
2. Open plugin settings in Obsidian
3. Enter project URL: `https://ewlygzvnvqyvszdpwbww.supabase.co`
4. Enter anon key (from loove-keys: `supabase` / `anon_key`)
5. Enter Management API PAT (from Supabase dashboard)
6. Click "One-Click Setup" to create vault_files table + storage bucket
7. Sign in with Supabase auth credentials
8. Set Vault ID (generate or enter a custom one)
9. Verify System Vault ID is `loove-system`

### Stage 2: Translation Layer
1. Open Supabase SQL Editor
2. Run `sql/system_vault_rls_bypass.sql` (RLS policies for system notes)
3. Run `sql/translation_layer.sql` (triggers for 5 operational tables)
4. Run backfill commands (uncomment the UPDATE statements at the bottom)

### Stage 3: RAG Pipeline
1. Run `sql/rag_pipeline.sql` in Supabase SQL Editor
2. Add `project_url` to Supabase Vault secrets:
   - Supabase Dashboard > Project Settings > Vault
   - Name: `project_url`
   - Value: `https://ewlygzvnvqyvszdpwbww.supabase.co`
3. Deploy the Edge Function:
   ```bash
   cd supabase && supabase functions deploy generate-embedding
   ```
4. The pg_cron job will automatically process the embedding queue

### Stage 4: Obsidian Configuration
1. Disable Obsidian Sync for the LOOVE vault (if enabled)
2. Click "Sync Now" in plugin settings
3. System notes will appear under `loove/` folder:
   - `loove/shared-context/` — shared_context table
   - `loove/knowledge/d{N}/` — loove_index_entries by domain
   - `loove/tasks/` — openclaw_tasks
   - `loove/artists/` — artists table
   - `loove/trouble-reports/` — trouble_reports

## Recommended Obsidian Plugins

- *Dataview* — Query frontmatter as structured data
- *Smart Connections* — Local semantic search over vault
- *Graph View* (built-in) — Visual cross-reference map

## Editing System Notes

System notes are generated by Postgres triggers. When you edit them in Obsidian:
- Changes to frontmatter fields (status, priority, assignee) sync back to the source table
- Body content changes sync back for shared_context and trouble_reports
- Artists and knowledge entries are read-only in Phase 1
- The Postgres echo prevention system prevents infinite loops

## Troubleshooting

| Issue | Solution |
|-------|----------|
| System notes not appearing | Check that `systemVaultId` matches `loove-system` in settings |
| Sync errors on system notes | Run `sql/system_vault_rls_bypass.sql` |
| Embeddings not generating | Verify `project_url` in Vault secrets, check Edge Function logs |
| Backfill slow | ~3,500 rows; allow 2-3 minutes for initial population |
